Roadmap · 1.0.0 Architecture & Operating Guide

The historical V1–V12 work is consolidated here into one stable product story. The roadmap explains what the platform does, how the components interact, and how to run it.

1. Executive architecture

Business Requirement ↓ AI Requirement Understanding ↓ Test Generation ↓ Agent Orchestrator ↓ AgentRun / AgentStep ↓ Git / PR Change Impact Analysis ↓ Real UAT Execution ↓ Evidence & Results ↓ Quality Gate ↓ CI/CD Deployment Decision

2. System architecture

Web UI / API ↓ Spring Boot Application ├── Requirement Analysis ├── Test Design ├── Agent Orchestrator ├── Impact Analysis ├── UAT / Playwright Execution ├── Failure Analysis └── Quality Gate ↓ PostgreSQL + Evidence ↓ CI/CD / AWS Delivery

3. AI / Agent architecture

Requirement intent ↓ Agent Orchestrator ↓ ┌─────────────────────────────┐ │ AgentRun │ │ ├─ understand │ │ ├─ design │ │ ├─ automate │ │ ├─ execute │ │ ├─ analyze │ │ └─ recommend │ └─────────────────────────────┘ ↓ Governance / Policy ↓ Deterministic Tools ↓ Evidence

4. CI/CD architecture

Git Push ↓ GitHub Actions ↓ Maven Tests ↓ Docker / Playwright Image ↓ GitHub Container Registry ↓ AWS EC2 pulls immutable image ↓ Health Check ↓ Impact Analysis ↓ Real UAT ↓ Quality Gate ↓ Deploy / Block

5. Deployment architecture

Internet ↓ HTTPS / Nginx ↓ AWS EC2 ├── AI QA Engineer container └── PostgreSQL container │ persistent volume External delivery: GitHub → Actions → GHCR → EC2

6. Data & evidence flow

Requirement ↓ Test intent + cases ↓ AgentRun / AgentStep ↓ Execution result ↓ Screenshots / logs / evidence ↓ Failure & impact intelligence ↓ Risk decision ↓ Quality Gate result

7. Run locally · Docker (recommended)

  1. Clone the repository.
  2. Enter the project directory.
  3. Start the application and PostgreSQL with Docker Compose.
  4. Verify the health endpoint.
git clone https://github.com/stejas7/ai-qa-engineer.git cd ai-qa-engineer docker compose up -d docker compose ps curl http://localhost:8080/actuator/health

Expected health response: {"status":"UP"}. Use docker compose logs -f for runtime diagnostics.

8. Run locally · Java development

  1. Install Java 21 and Maven.
  2. Provide PostgreSQL using Compose or a local instance.
  3. Run the verification suite.
  4. Start Spring Boot.
mvn clean verify mvn spring-boot:run curl http://localhost:8080/actuator/health

Use this mode for Java development, unit tests, refactoring and API work. Docker remains the preferred reproducible demo path.

9. Production deployment

Git push → GitHub Actions → Maven verification → Docker image → GHCR → EC2 pulls exact image → container restart → health check → UAT → Quality Gate

The production model builds the image once in CI and deploys the same immutable image to EC2. The EC2 host should not rebuild Maven or Playwright during normal deployment.

10. Verification checklist

  • Application health is UP.
  • PostgreSQL container is healthy and its volume is preserved.
  • HTTPS endpoint is reachable through Nginx.
  • AgentRun and AgentStep execution is persisted.
  • UAT produces real execution evidence.
  • Impact analysis produces a risk recommendation.
  • Quality Gate produces the final delivery decision.

11. Architecture principles

AI plans and reasons. AI turns business intent into structured test intelligence.

Deterministic tools execute. Playwright and application services perform the actual work.

Governance controls autonomy. Policy and approval boundaries prevent unsafe actions.

Evidence explains what happened. Results remain traceable to execution steps.

The Quality Gate decides. Delivery is allowed only when evidence and policy satisfy the release criteria.

12. Troubleshooting quick guide

Health fails: check docker compose ps and application logs.

Database fails: inspect PostgreSQL logs and preserve the named volume.

Playwright fails: verify the deployed image contains the Playwright runtime; do not install browsers during a request.

Docker disk pressure: check df -h / and Docker/containerd usage before pruning.

CI deployment fails: inspect the failing workflow stage first; do not blindly rerun an old deployment.

HTTPS fails: verify Nginx, port 443, certificate and DNS resolution.
