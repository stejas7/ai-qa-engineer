# Scorpion 2.0.0 — Autonomous UAT QA

## Product reset

Scorpion 2.0.0 changes the product experience from a collection of manually operated V1-V10 pages into one autonomous QA mission.

> Give Scorpion an end-to-end business requirement and a UAT environment. Scorpion automatically moves from requirement understanding to test design, automation generation, UAT execution and failure analysis.

## V1-V5 capabilities inside one mission

1. **V1 — Requirement understanding**
   - Business requirement analysis
   - Business rules
   - Acceptance/test scenarios
   - AI provider with deterministic demo fallback

2. **V2 — Test design**
   - Functional coverage
   - Negative coverage
   - Boundary coverage
   - Traceability coverage

3. **V3 — Automation generation**
   - Playwright Java test artifact generation
   - UAT URL and generated test metadata

4. **V4 — UAT execution**
   - Playwright execution
   - Supported browser actions
   - PASS/FAIL result
   - Screenshot evidence

5. **V5 — Failure analysis**
   - Automatic failure classification
   - Severity
   - Probable cause
   - Recommendation
   - Retry signal

## Primary UI

`/scorpion.html`

The user should not manually navigate V1 → V2 → V3 → V4 → V5. Those capabilities are internal stages of one autonomous mission.

## API

```text
POST /api/scorpion/missions
GET  /api/scorpion/missions
GET  /api/scorpion/missions/{id}
```

Start request:

```json
{
  "title": "Customer Journey UAT",
  "requirement": "A customer must be able to register, login, search for a product and complete checkout.",
  "uatUrl": "https://uat.example.com"
}
```

## Important boundary

Scorpion's execution engine remains deterministic. AI may generate and classify, but browser actions are executed through the controlled Playwright service. Unsupported actions fail explicitly rather than being guessed.
